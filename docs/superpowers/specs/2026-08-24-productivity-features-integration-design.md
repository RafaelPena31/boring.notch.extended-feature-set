# Productivity Features Integration Design

**Date:** 2026-08-24

**Status:** Approved

## Goal

Integrate four existing pull-request implementations into the current `main` branch as cohesive, locally available Boring Notch features:

- Complete clipboard history, sourced from PR #1449.
- Calendar event Live Activity, sourced from PR #1382.
- Pomodoro timer integrated with the notch, sourced from PR #1347.
- Keep Awake / Caffeine, sourced from PR #1311.

The integration will reuse the useful feature code while adapting shared surfaces to the current project instead of applying the pull requests verbatim.

## Product Decisions

- All four features must fit the current visual language and existing navigation.
- Clipboard history is disabled by default and must be explicitly enabled in Settings.
- Calendar Live Activity is optional and depends on the app's existing calendar access.
- Pomodoro only runs after explicit user action.
- Keep Awake only creates a power assertion after explicit user action.
- No test target or automated TDD workflow will be introduced for this project. Validation will use incremental builds, smoke checks, and diff review.

## Integration Strategy

Port each feature independently in this order:

1. Clipboard history.
2. Calendar Live Activity.
3. Pomodoro.
4. Keep Awake.

Feature-owned files remain isolated. Shared files such as `ContentView.swift`, `BoringViewCoordinator.swift`, tab selection, Settings, defaults, application lifecycle, and the Xcode project are edited deliberately after comparing all four PRs. Packaging artifacts and unrelated changes are excluded, including the DMG and build script from PR #1382.

## Clipboard History

### User experience

Clipboard history appears as an additional notch tab after it is enabled in Settings. It supports text, web links, images, and file references. Users can copy an entry again, open a link, reveal a file in Finder, delete one entry, or clear the history.

### Components

- `ClipboardItem` models stored content and provides stable identity.
- `ClipboardMonitor` observes `NSPasteboard.general.changeCount` only while the feature is enabled.
- `ClipboardStore` owns the newest-first history and deduplication behavior.
- `ClipboardPersistenceService` stores metadata and image blobs under Application Support.
- `ClipboardActionService` implements copy, open, reveal, delete, and clear actions.
- `ClipboardView` renders the tab and its empty, populated, and confirmation states.

### Privacy and failure behavior

Clipboard monitoring ignores transient, autogenerated, and concealed pasteboard content. Oversized images are skipped rather than partially persisted. Disabling the feature stops monitoring. Clearing history removes both metadata and stored blobs. Corrupt persistence data should be handled defensively without preventing the app from launching.

## Calendar Event Live Activity

### User experience

When enabled and a future calendar event exists, the closed notch shows a compact representation of the next event and its timing. The activity updates as the event approaches or begins, disappears when no relevant event remains, and does not replace normal calendar notifications.

### Components and data flow

- The existing `CalendarManager` remains the source of permissions and event data.
- `CalendarLiveActivityViewModel` derives the currently relevant event and display state.
- `CalendarLiveActivity` renders the compact closed-notch presentation.
- `ContentView` composes the activity without changing the normal closed-notch layout when the feature is unavailable.

If calendar permission is missing, access fails, or no event is eligible, the activity is omitted and the existing notch remains unchanged.

## Pomodoro

### User experience

Pomodoro appears as a dedicated notch tab with focus, short-break, and long-break phases. Users can start, pause, resume, skip, and reset a session. Durations and cycle counts are configurable in Settings. While running, a compact timer remains visible around the closed notch without colliding with existing music content.

### Components and timing

- `PomodoroManager` owns the state machine, phase progression, timing, and notification requests.
- `PomodoroView` renders the open-notch controls and progress.
- Settings expose work duration, break durations, long-break cadence, automatic progression, sound, and notification preferences supported by the imported implementation.
- The application lifecycle reconnects elapsed time to wall-clock deadlines so timer state remains correct after stalls or sleep.

Notification or sound delivery failures must not stop or reset the timer.

## Keep Awake / Caffeine

### User experience

Keep Awake is available from the expanded-notch header and Settings. Its active state is visible and can be toggled with one action. It remains inactive by default.

### Components and lifecycle

- `CaffeineManager` creates and releases native IOKit power assertions.
- The manager supports the assertion modes and optional durations already represented by the selected PR when they fit the current UI.
- The app releases any active assertion when the user disables the feature or the application terminates.

Failure to create an assertion is surfaced in the UI and must leave the manager in an inactive state.

## Shared UI and State

- Clipboard and Pomodoro extend the existing tab model and `TabSelectionView`.
- Calendar Live Activity and the Pomodoro compact timer are composed in the closed-notch presentation with explicit spacing rules.
- Keep Awake extends the expanded header without replacing existing controls.
- Settings are grouped by feature, with defaults stored through the project's existing Defaults conventions.
- Shared app services use the project's current `ObservableObject` ownership patterns to minimize unrelated refactoring.

## Validation

After each feature is integrated:

1. Build the macOS app with Derived Data under `/tmp`.
2. Inspect compiler errors and warnings introduced by the feature.
3. Perform feature-specific smoke checks where local permissions permit.
4. Review the diff for unrelated PR content, generated binaries, packaging scripts, sandbox changes, or accidental removals.

After all four integrations, perform a clean full build and verify that existing Home, Shelf, Calendar, media, Settings, and notch-open/closed flows remain available.

## Out of Scope

- Importing unrelated fixes or refactors from the four PR branches.
- Shipping DMG files or packaging scripts included in PR #1382.
- Adding a test target or automated test suite.
- Redesigning the complete tab system, Settings architecture, calendar subsystem, or closed-notch renderer.
- Publishing, pushing, or opening a new pull request.
